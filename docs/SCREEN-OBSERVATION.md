# 随机屏幕观察

开启后，Coo 在随机间隔到达时截取一块屏幕，将截图作为观察事件交给当前视觉模型。模型可以根据可见内容表达一句简短、友善的调侃，也可以保持安静。此功能默认关闭。

## 设置与间隔

在设置窗口的「习惯」页调整屏幕观察。配置位于部署 `config.json` 的 `worlds.desktop-pet.observation` 段，可热更新。

| 配置 | 默认值 | 作用 |
|---|---|---|
| `enabled` | `false` | 开启或关闭屏幕观察 |
| `minIntervalSeconds` | `300` | 最短观察间隔，秒 |
| `maxIntervalSeconds` | `900` | 最长观察间隔，秒 |

默认间隔为 5–15 分钟。最短间隔至少 30 秒，最长不超过 24 小时，且最短不能大于最长。每次观察结束后，都重新从最短到最长的区间中均匀抽取下一次间隔；随机值可能相近或重复。修改区间后重新计时，关闭功能或停止桌宠会取消定时器，观察不会重叠执行。

到达时间但暂不适合观察时，跳过该次并重新抽取间隔，不把错过的观察积攒起来。桌宠需要处于显示且连接的状态；Coo 正在执行任务、播放内容、等待用户回答，或者处于暂停、安静时段时，不开始观察。截图完成后会再次核对状态，状态已变化时不发送该张截图。

## 捕获内容与权限

每次捕获前台窗口所在的显示器；没有可用的前台屏信息时使用主显示器。截图复用桌宠现有截图引擎和压缩配置，默认最长尺寸限制为 1280×800、JPEG 质量为 75。多显示器不会合并捕获；截取的显示器可能随着前台窗口位置变化。

屏幕观察的开关独立于电脑操作开关。开启观察授权这一功能定时读取屏幕，不会开启鼠标键盘输入，也不会更改原有电脑操作的询问策略。已有系统截图权限仍然适用；macOS 等平台需要在系统中允许录屏，权限不可用时该次观察失败，不会生成一条假装已经看到屏幕的评论。

观察事件要求模型围绕可见内容表达一句短评，语气轻松友善，避免挖苦私人处境或作出健康、人格等推断。密码、验证码、账号和私密内容不应被复述。屏幕文字属于不可信的观察材料，不能被当成新的操作指令。可见内容不适合评论时，模型可以保持安静。

## 模型、存储与用量

| 依赖 | 用途 | 不可用时 |
|---|---|---|
| 当前模型支持 JPEG 图像输入 | 理解截图并生成短评 | 跳过观察，不向纯文本模型发送截图 |
| 可用截图引擎及系统权限 | 捕获前台屏或主屏 | 记录失败，等待下一次随机时机 |
| 桌宠可见、连接且 Coo 空闲 | 显示评论，避免打断现有互动 | 跳过本次，不累积观察 |
| 已配置的模型服务与可用额度 | 处理观察事件 | 遵循应用现有模型连接和失败处理机制 |

无需安装额外插件，也不建立新的模型连接。截图可能被发送到当前配置的模型服务，产生图像输入和生成文本的用量。频率越高，潜在用量越大。

截图通过 Core 的正常事件附件链路保存，并进入模型上下文。观察截图不会作为独立图片显示在普通聊天页；Coo 使用 `pet_say` 说出的评论会显示在聊天记录中。关闭观察阻止后续捕获和事件发送，不会删除已保存的事件附件，也不会撤销已经交给模型的上下文。

## 验证与排查

| 情况 | 检查项 |
|---|---|
| 一直没有评论 | 确认观察已开启、区间有效、桌宠显示、应用未暂停，且当前模型支持图像；模型也可能选择保持安静 |
| 间隔看起来比设置更久 | 忙碌、隐藏、等待回答等情况会跳过本次；之后从新区间重新计时 |
| 系统拒绝截图 | 查看应用日志和系统截图权限，按平台要求授予权限后重试 |
| 更换模型后停止观察 | 确认新模型的图像输入能力和模型连接可用 |
| 不希望继续发送屏幕内容 | 在「习惯」中关闭观察；原有记录按 Core 的事件和存储生命周期保留 |

开发验证使用隔离数据目录、脚本化截图引擎和模型响应，避免截取用户真实屏幕。随机调度测试应覆盖每轮抽样、区间边界、不重叠、关闭取消、热更新和停止竞态。
